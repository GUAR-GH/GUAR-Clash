# Security reporting

Do not post live credentials, private profiles, subscription links or exploitable
vulnerability details in public issues. Use the repository's **Security → Report a
vulnerability** flow when private vulnerability reporting is enabled. Maintainers
must configure and verify a private reporting channel before distributing a new
independent release. No unverified contact address is supplied by this template.

For an ordinary bug, use the issue tracker with a redacted reproduction. If an
access token or engine controller secret has been disclosed, rotate that credential
with its issuing service or engine and remove the public copy where possible.

Supported security-update versions will be listed with an approved release.
Historical downloads being preserved does not imply continued security maintenance.
